# RikkaHub 复现：让 Agent 打开 rikkahub/rikkahub 并标星

这份是给 **RikkaHub 里的 Agent** 的任务提示词（正文在代码块里，整段复制粘贴）。
它测的是**运行时那条路**：不注入代码、不改任何应用，靠无障碍读取界面 + 注入手势，
让 Agent 自己把一个陌生的应用界面走通。

和之前那个闹钟 demo 的区别很重要：闹钟那次是**静态注入**（把编译好的代码送进目标进程，
调用它自己的接口）。这次是**纯动态**——Agent 只用"看"和"点"，目标应用完全不知道被操控。

## 前置检查

1. **PosEdMCP 在跑，无障碍已启用**：打开 PosEdMCP，STATUS 里
   Accessibility 显示 enabled。没有的话点旁边的 Accessibility 按钮去开。
2. **GitHub 应用已登录**（`com.github.android`），否则标星会要求先登录。
3. **关掉「确认注入输入」**：一次 UI 操作要点很多下，每点一下都弹窗是没法用的。
   在 PosEdMCP 主界面「CONFIRMATION POLICY」里把 **Confirm injected input** 关掉。
   同样的理由，**Confirm screen capture and UI dumps** 也可以关掉。
   —— 这两个开关是我特意做成可放宽的：走的是模块/无障碍特权，不是 shell。
   而 `root_shell_exec` 无论如何都弹窗，且不可关闭。
4. **别用 `adb shell am force-stop dev.posedmcp` 重启它**——force-stop 会解除无障碍绑定，
   也就毁掉了保活。要重启就 `kill <pid>`，系统会自动重新绑定。

## 提示词（整段复制给 Agent）

```text
你的任务：在本机的 GitHub 应用里打开仓库 rikkahub/rikkahub，并给它标星。
做完要能让我看到结果，而不是只报告"成功了"。

# 你能用的工具（全部不需要 root）

- `launch_app(package)` — 把应用切到前台，等同于点它的图标
- `ui_dump(mode="a11y")` — 读当前界面的控件树：text / desc / id / bounds / center /
  clickable。**center 里的坐标就是你要点的位置。**
- `input_inject(action="tap", x=..., y=...)` — 点。也支持 swipe / long_press / text / key
- `screen_capture(mode="a11y")` — 截屏。控件树读不清时用它看一眼
- `foreground_app()` — 当前前台是哪个应用
- `events_poll()` — 最近的窗口切换等事件

# 工作方式：看 → 决定 → 动 → 再看

驱动一个不熟悉的界面，唯一可靠的办法是**每一步都先看**。不要凭记忆猜坐标。

1. `launch_app(package="com.github.android")`，等两三秒
2. `ui_dump(mode="a11y")` 看落地在哪。如果还在别的应用，再 `foreground_app()` 确认
3. 从控件树里找到你要点的那个节点，用它的 `center` 坐标 `input_inject` 点
4. 等一两秒，**再 dump 一次**，确认界面确实变了、变的方向是对的
5. 重复，直到达成目标

# 大概的路径（按实际界面走，不要照抄）

GitHub 应用里通常是：首页 → 搜索 → 输入 `rikkahub/rikkahub` → 打开仓库页 →
在仓库页上找到 Star 按钮点一下。

仓库页上大概会看到这些（**以你 dump 出来的为准**）：
- 仓库名、作者、README
- 一个 **Star** 按钮，点过之后它会变成 **Starred** 之类
- 「Star」也可能藏在某个 `...` 或 overflow 菜单里

`text`/`desc` 里带 Star、星形图标、`star` 这类字样的节点就是目标。中文界面下可能是
「标星」「已标星」。

# 验证（这一步不能省）

点完之后：
- 按钮的文字/描述应该**从 Star 变成 Starred**（或反之）
- 如果不确定，`screen_capture(mode="a11y")` 看一眼，或者 `ui_dump` 再读一次那个按钮
- 把这两次的差别告诉我

**"点了"和"点到了"是两回事。** 之前有一次实验里，调用返回了成功、应用也真的建了对象，
但参数没被正确解析，结果是一个默认值——只有看结果才发现。所以一定要读状态。

# 规则

- **先看再点。** 每一步动手前先 dump，用坐标而不是猜。
- **点完必须再看一次。** dump 出来没变化，说明没点中，别继续往下点。
- **同一个动作连续失败三次就停下**，把当时的控件树给我看，问我要不要换个思路。
  不要在界面上乱点试图"试出来"。
- **不要点任何看起来会改数据的东西**：不要在别人的仓库里点 fork、不要点赞、
  不要发评论、不要改设置。这个任务只有一件事：打开那个仓库并给它标星。
- 每次 `input_inject` 如果你那边还开着确认，我每次都会看到弹窗；关掉了就直接执行。
  不管怎样，**不要在 reason 里写"为了完成任务"这种废话**，写清楚这一步在做什么。
```

## 这个 demo 在测什么

| 能力 | 之前 | 现在 |
|---|---|---|
| 读取界面 | `uiautomator` 根命令，每次一个 root 弹窗 | 无障碍，**零 root** |
| 点击/滑动 | `input` 根命令，每次一个 root 弹窗 | 无障碍手势，**零 root** |
| 输入文字 | `input text`，转义麻烦、依赖 root | `ACTION_SET_TEXT` 写到焦点输入框 |
| 启动应用 | 只能 root shell 跑 `monkey` | `launch_app`，**零 root** |
| 应用切后台还活着 | 20 秒内被冻结，端点失联 | 无障碍绑定保活，实测 90 秒零冻结线程 |

换句话说：这条路走通之后，**常规的界面自动化完全不需要 root**——
root 只留给真正需要它的场合，也就是那些用户必须逐条读命令的场合。

## 一个要注意的取舍

关掉「确认注入输入」意味着 Agent 可以随便点你的屏幕。这是有意的：
每点一下都弹窗等于没法自动化。但这个开关**只影响无障碍/模块特权那条路**，
`root_shell_exec` 永远弹窗、不可关闭——那是真正的权限边界，不会因为放宽设置而消失。

如果你不放心，可以先开着，拿这个 demo 走几步看看 Agent 的行为是否符合预期，
再决定要不要关。
